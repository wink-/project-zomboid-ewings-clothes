# Installed-build evidence

Inspected 2026-10-22, Windows. Steam app 108600 manifest reports build **25485521**. `zombie/core/Core.class` static initializer constructs `GameVersion` with integer 42, integer 21 and an empty suffix: **42.21**. This was read offline from `projectzomboid.jar`, without running game code. Exact selected input hashes are in `VALIDATION.json`.

## Clothing and equipment

- `media/scripts/generated/items/clothing.txt`, item `Base.Tshirt_DefaultTEXTURE`: `ItemType=base:clothing`, `BodyLocation=base:tshirt`, `BloodLocation=Shirt`, `FabricType=Cotton`, insulation 0.2, wind resistance 0.05, `WorldStaticModel=TShirt_Ground`, cotton-ripping tag. The mod uses this minimal native contract, one independent namespace, and its own icon/XML/texture/name. Weight 0.3 is explicitly a mod choice.
- `media/clothing/clothingItems/Tshirt_DefaultTEXTURE.xml`: male/female model fields empty; hue/tint disabled; a base texture atlas is provided. `Tshirt_WhiteTINT.xml` shows the alternate random tint flag. Empty garment models are intentional for this type of native body-layer clothing.
- `media/scripts/generated/models_characters.txt`: vanilla `MaleBody` and `FemaleBody` resolve to `Skinned/MaleBody` and `Skinned/FemaleBody`; both are animated meshes. Their corresponding installed text `.x` files provide preview geometry and UVs locally; none is copied to distribution.
- `media/lua/shared/NPCs/BodyLocations.lua`: native TSHIRT location appears between tank top and shirt in render order. `media/lua/shared/TimedActions/ISWearClothing.lua` uses the TSHIRT pullover animation, then sets the worn item in its declared body location and sends the native clothing update. No mod-specific equip Lua is necessary.

## UV layout and source art

- The inspected body meshes contain 617 vertices/916 triangles (male), 660 vertices/984 triangles (female). Front torso uses the continuous central atlas island centered at U=0.5. Back halves use islands centered near U=0.207 and U=0.793. The front center has native negative Z (lateral upper-chest edges can approach Z=0); increasing front U maps to increasing native X. Converted locally from DirectX Y-up to Blender Z-up for preview, this reads left-to-right from the front.
- Native `TShirt_White.png` and `ClothingTShirt.png` were inspected locally for dimensions, alpha and the body-atlas layout. Transparent pixels retain RGB data, so a simple viewer alone can misleadingly show long sleeve/skin-colored areas. Alpha sampling and the first render exposed an overly long original sleeve mask; the final original mask ends at native atlas Y=42, with the final chest print raised to avoid breast-contour distortion. No native alpha mask or pixels were copied into the output.
- Final original texture is 1024x1024 RGBA, a 4x atlas drawing using original flat polygons. Yellow print occupies pixel box X=424..599, Y=340..373 (native 256px convention: X=106..149.75, Y=85..93.25). The print stays on the front UV island, below the neckline and away from side seams. Native decal definitions such as `TShirt_Rock_1.xml` were inspected as evidence for the separate decal mechanism; this mod deliberately bakes text into its own single texture instead of registering or selecting a random decal group.
- Local Blender 5.2.3 LTS renders both body meshes front/back with only the original texture plus neutral gray material. The output preview is an image only. No `.blend`, exported mesh, vanilla texture, skeleton or extracted asset is distributed. Preview render scripts read installed meshes locally if rerun.

## Actual native consumers

- `ItemVisual.getHue(ClothingItem)` returns/reset hue to zero with `allowRandomHue=false`. `ItemVisual.getTint(ClothingItem)` uses white with `allowRandomTint=false` unless an inventory item is explicitly custom-colored. The mod does not set custom colors, tint multiplier fields or the `canbedyed` tag. Thus the normal native creation path preserves the baked purple/yellow design; third-party debug recoloring or other mods can still override visuals.
- `ModelInstanceTextureCreator.addClothingItem` reads `getBaseTexture`, `getTextureChoice`, tint and hue. It reads blood, dirt, patches and holes from `ItemVisual`; the renderer subsequently composites them. `ClothingItem` constructor defaults its mask folders to `media/textures/Body/Masks`, while character texture code uses native blood/hole masks. The mod uses these references through the native pipeline and adds no custom blood/hole assets or mask suppression.
- `OutfitManager.getClothingItem` resolves a GUID through `ZomboidFileSystem`, then loads the XML through `ClothingItemAssetManager`. `ZomboidFileSystem.loadFileGuidTable` loads/merges tables from each mod's `common` and version directory. The mod therefore includes exactly one owned GUID/path record in `common/media/fileGuidTable.xml`, never a copy/replacement of the vanilla table.
- `ItemModelRenderer` resolves `WorldStaticModel`, obtains clothing visuals/base texture and tint, and uses native texture-name resolution. `models_clothes.txt` maps `TShirt_Ground` to the vanilla `WorldItems/Clothing/Bob_TShirt_Ground` mesh, scale 0.33. Referencing it avoids bundling a model. Ground render orientation was not tested in game.
- `ChooseGameInfo.readModInfoAux` consumes `modversion`, `versionMin` and `versionMax`. The release is bounded to inspected 42.21. Vanilla English item names are now `media/lua/shared/Translate/EN/ItemName.json`; the mod provides a one-key additive JSON file in the same current format.

These are static findings, not proof of a successful game load, animated render or network replication. No game/server process was launched or stopped, no mods installed/enabled, no saves accessed, no settings edited and no online publication performed. All created files are inside this isolated workspace. Unrelated Ewing's projects were not opened or modified.

The main B42 skill was read; its referenced companion/validator resources were unavailable in this execution environment. `tools/validate_and_package.py` supplies explicit equivalent release checks rather than claiming the unavailable bundled validator ran.
